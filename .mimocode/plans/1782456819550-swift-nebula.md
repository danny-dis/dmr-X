# Plan: Provider-Agnostic Response Cache for All Modalities

## Goal
Expand the existing provider-agnostic response cache (currently chat-only) to cover ALL request modalities so cached responses persist regardless of which provider answered.

## Current State
- `services/cache/src/cache.service.ts` implements provider-agnostic caching (key = request body hash + tenant + request type)
- Only wired into `chat.routes.ts` for non-streaming chat requests
- 9 other route files have zero caching
- `invalidateTenantCache()` is a no-op (just logs)
- `MemoryCache` lacks a `keysByPrefix()` method needed for prefix-based invalidation

## Changes

### 1. Add `keysByPrefix()` to `packages/db/src/cache.ts`
Add a method to `MemoryCache` and `NamespacedCache` that returns all keys matching a prefix. This enables `invalidateTenantCache` to actually work.

```typescript
// In MemoryCache class
keysByPrefix(prefix: string): string[] {
  return this.keys().filter(k => k.startsWith(prefix));
}

// In NamespacedCache interface + createNamespacedCache
keysByPrefix: (prefix: string) => string[];
```

### 2. Expand `services/cache/src/cache.service.ts`
- Widen `requestType` in `CacheOptions` to cover all modalities: `'chat' | 'embedding' | 'image' | 'audio_tts' | 'audio_stt' | 'audio_separation' | 'video' | '3d' | 'ocr' | 'rerank' | 'moderation' | 'other'`
- Add per-modality default TTLs:
  - `embedding` = 3600s (1hr, deterministic)
  - `ocr` = 1800s (30min, deterministic)
  - `rerank` = 1800s (30min)
  - `moderation` = 1800s (30min)
  - `chat` = 300s (5min)
  - `image` = 600s (10min)
  - `audio_tts` = 600s (10min)
  - `video` = 600s (10min)
  - `3d` = 600s (10min)
  - `audio_stt` = 600s (10min)
  - `audio_separation` = 600s (10min)
- Implement `invalidateTenantCache()` using `keysByPrefix()` to enumerate and delete all keys with the tenant prefix
- Add helper to hash large binary fields (base64 audio/image/video) before key generation to keep keys small

### 3. Create reusable route cache helper in `services/cache/src/cache.service.ts`
Add `checkRouteCache()` and `storeRouteCache()` functions that encapsulate the check/store pattern with skip-cache predicates:

```typescript
export function checkRouteCache(
  requestType: string,
  tenantId: string | undefined,
  requestBody: Record<string, unknown>,
  skipCache?: (body: Record<string, unknown>) => boolean
): CacheEntry | null

export function storeRouteCache(
  requestType: string,
  tenantId: string | undefined,
  requestBody: Record<string, unknown>,
  response: unknown,
  options?: { skipCache?: (body: Record<string, unknown>) => boolean; ttlSeconds?: number }
): void
```

### 4. Wire cache into all 9 uncached route files

Each route gets ~5 lines added (check before routing, store after response):

| Route File | requestType | Skip-cache predicate |
|---|---|---|
| `embeddings.routes.ts` | `embedding` | `encoding_format === 'base64'` |
| `images.routes.ts` | `image` | `response_format === 'b64_json'` |
| `audio.routes.ts` (speech) | `audio_tts` | none (always cache) |
| `audio.routes.ts` (transcription) | `audio_stt` | none (always cache) |
| `audio-separation.routes.ts` | `audio_separation` | none |
| `video.routes.ts` | `video` | none |
| `3d.routes.ts` | `3d` | none |
| `ocr.routes.ts` | `ocr` | none |
| `rerank.routes.ts` | `rerank` | none |
| `moderation.routes.ts` | `moderation` | none |

Pattern for each route:
```typescript
// Before routing
const tenantId = (request as any).tenant?.id;
const cached = checkRouteCache('modality', tenantId, body);
if (cached) { reply.header('X-Cache', 'HIT'); return cached.response; }

// ... existing routing logic ...

// After response
storeRouteCache('modality', tenantId, body, response);
reply.header('X-Cache', 'MISS');
```

### 5. Cache streaming chat responses (post-completion)
In `chat.routes.ts`, after the streaming response completes (`[DONE]`), assemble the accumulated chunks and store in cache. This benefits subsequent non-streaming requests for the same content.

### 6. Export new helpers from `services/cache/src/index.ts`
Export `checkRouteCache` and `storeRouteCache`.
