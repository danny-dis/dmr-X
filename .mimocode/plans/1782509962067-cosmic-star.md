# Plan: Add Headroom Compression Option to Every API Key Issued

## Summary

The Headroom compression integration is already partially built — the `CompressionService` exists, the database schema has compression columns on `api_keys`, and compression is applied in chat/anthropic/gemini routes. The gap: **compression settings are never set when creating or updating API keys**. This plan closes that gap.

## What Exists

- `apps/gateway/src/services/compression.ts` — full `CompressionService` with `getApiKeyConfig()` / `updateApiKeyConfig()`
- `packages/db/src/migrations/025_compression_settings.sql` — columns already exist: `compression_enabled`, `compression_algorithm`, `compression_reversible` on `api_keys`
- `apps/gateway/src/routes/compression.routes.ts` — CRUD endpoints for compression config per API key
- `apps/gateway/src/routes/chat.routes.ts` / `anthropic.routes.ts` / `gemini.routes.ts` — compression applied in request pipeline when enabled
- `headroom-ai` package installed

## Changes Required

### 1. Add compression fields to `CreateApiKeySchema`

**File:** `apps/gateway/src/routes/admin.routes.ts:234`

Current schema:
```ts
const CreateApiKeySchema = z.object({
  tenant_id: z.string().uuid(),
  name: z.string().max(255).optional(),
  scopes: z.array(z.string()).optional(),
  allowed_tools: z.array(z.string()).optional(),
  expires_at: z.string().datetime().optional().nullable(),
});
```

Add:
```ts
compression_enabled: z.boolean().optional(),
compression_algorithm: z.enum(['auto', 'smartcrusher', 'codecompressor', 'kompress']).optional(),
compression_reversible: z.boolean().optional(),
```

### 2. Store compression settings during key creation

**File:** `apps/gateway/src/routes/admin.routes.ts:2532-2573`

In the `POST /admin/api-keys` handler, after the INSERT, store compression settings if provided. Use `compressionService.updateApiKeyConfig()` or direct SQL since the columns already exist.

Modify the INSERT to include compression columns, or follow up with an UPDATE if compression options are present.

### 3. Update `createApiKeyForTenant` helper

**File:** `apps/gateway/src/routes/admin.routes.ts:868-893`

Add optional compression parameters to this internal helper function signature and pass them through to the INSERT.

### 4. Add PATCH endpoint for compression on existing keys

**File:** `apps/gateway/src/routes/admin.routes.ts`

Add a new endpoint following the existing pattern (like `/admin/api-keys/:id/tools`):

```
PATCH /admin/api-keys/:id/compression
```

Body: `{ compression_enabled?: boolean, compression_algorithm?: string, compression_reversible?: boolean }`

This delegates to `compressionService.updateApiKeyConfig()`.

### 5. Include compression fields in API key list response

**File:** `apps/gateway/src/routes/admin.routes.ts:2604-2613`

Update the SELECT in `GET /admin/api-keys` to include `compression_enabled`, `compression_algorithm`, `compression_reversible` so the admin UI can display them.

### 6. Update `CreateTenantApiKeySchema` if applicable

**File:** `apps/gateway/src/routes/admin.routes.ts:242-245`

Add the same compression fields to the tenant-facing API key creation schema.
