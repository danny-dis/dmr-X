## What We're Adopting from Pi (into native agent)

### Priority 1: Tool Lifecycle Hooks (beforeToolCall / afterToolCall)
**Why:** Enables approval gates, audit logging, custom error handling without modifying individual tools.

**Pi's pattern:** `beforeToolCall(context, signal) => { block?: boolean, reason?: string }` and `afterToolCall(context, signal) => { content?, details?, isError?, terminate? }`

**Implementation:**
- `packages/utils/src/tool-executor.ts` — Add hook callbacks to `executeTool()`
- `apps/gateway/src/routes/agentic.routes.ts` — Wire hooks into the agentic loop
- `apps/gateway/src/routes/tools.routes.ts` — Wire hooks into tool loop

### Priority 2: Steering and Follow-Up Queues
**Why:** Lets users inject messages during agent execution or queue work for after idle. Currently impossible — agent runs one request to completion.

**Pi's pattern:** `agent.steer(message)` injects after current tool batch. `agent.followUp(message)` queues for idle. Two queue modes: `"all"` or `"one-at-a-time"`.

**Implementation:**
- `apps/gateway/src/routes/agentic.routes.ts` — Add steering/follow-up queue support to conversation state
- `packages/utils/src/conversation-state.ts` — Extend `ConversationState` with queues
- SSE events: emit `steering_injected` and `follow_up_injected` events

### Priority 3: Thinking/Reasoning Level Support
**Why:** Models like Claude support extended thinking with token budgets. DMR-X currently exposes no thinking parameter.

**Pi's pattern:** `thinkingLevel` on agent state (off/minimal/low/medium/high/xhigh) + `thinkingBudgets` per-level token limits. Mapped to provider-specific options.

**Implementation:**
- `apps/gateway/src/routes/agentic.routes.ts` — Add `thinkingLevel` and `thinkingBudgets` to request schema
- `packages/utils/src/sdk-config.ts` — Map thinking levels to provider-specific params (Anthropic `thinkingBudgetTokens`, OpenAI `reasoningEffort`, Google `thinking.budgetTokens`)

### Priority 4: Abort and Error Recovery
**Why:** No way to cancel a running agent or retry after failure.

**Pi's pattern:** `agent.abort()` with AbortSignal propagation. `agent.continue()` resumes from last state. `shouldStopAfterTurn` callback for graceful early termination.

**Implementation:**
- `apps/gateway/src/routes/agentic.routes.ts` — Add AbortController per conversation, expose cancel endpoint
- Add `POST /agentic/chat/:conversationId/cancel` route
- Add `shouldStopAfterTurn` callback support

### Priority 5: Context Compaction
**Why:** Long conversations hit context limits and fail. No pruning mechanism exists.

**Pi's pattern:** Estimates token count, generates structured summary (Goal, Progress, Key Decisions, Next Steps), replaces old messages with summary while keeping recent context.

**Implementation:**
- `packages/utils/src/conversation-state.ts` — Add `compact()` method
- `apps/gateway/src/routes/agentic.routes.ts` — Auto-compact when approaching context limit
- Use router to generate summary via LLM call
