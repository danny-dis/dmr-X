# DMR-X Critical Issues Prioritized Fix Plan

## Overview

Based on comprehensive analysis of DMR-X, this plan prioritizes fixes across three phases:
- **P0**: Security vulnerabilities and data loss risks (immediate)
- **P1**: Production readiness issues (near-term)
- **P2**: UX/performance improvements (future)

---

## P0 — Security & Data Loss (Immediate)

### 1. Sandbox Cgroup Isolation & Bash Allowlist (CRITICAL)
**Files**: `services/sandbox/`, `apps/gateway/src/routes/tools.routes.ts`
**Issue**: No per-process resource limits, bash tool has trivially bypassable blocklist
**Impact**: DoS via fork bomb/memory allocation; command injection bypass
**Approach**:
- Add cgroup-based resource limits per sandbox process (memory: 512MB, CPU: 50%, pids: 50)
- Replace bash blocklist with allowlist of safe commands (git, npm, ls, node, etc.)
- Add argument validation to prevent injection via special characters
- Add network namespace isolation (`unshare --net` on Linux) for sandbox jobs
**Testing**: Fork bomb detection, memory limit enforcement, allowlist validation
**Effort**: 2-3 days

### 2. Path Traversal in Coding Tools (CRITICAL)
**Files**: `services/sandbox/src/executor.ts`
**Issue**: `safePath()` vulnerable to symlink traversal
**Impact**: Arbitrary file read/write outside workspace
**Approach**:
- Resolve symlinks before path validation
- Use `realpath()` to get actual path
- Validate resolved path starts with workspace
**Testing**: Symlink-based attack vectors
**Effort**: 0.5 days

### 3. SSRF URL Validation for Provider Base URLs (MEDIUM)
**Files**: `apps/gateway/src/routes/admin-ssrf.ts`, adapter executors
**Issue**: Provider `baseUrl` stored in DB could point to internal IPs
**Impact**: Potential internal network scanning
**Approach**: 
- Note: The existing SSRF protection in `admin-ssrf.ts` is actually solid (DNS-rebinding protection, IP blocklist)
- Add validation when provider URLs are saved via admin API
- Ensure all outbound fetches use the validated lookup function
**Testing**: Attempt to register provider with internal IP
**Effort**: 0.5 days

### 4. Migration Version 18 Mismatch (CRITICAL)
**Files**: `packages/db/src/client.ts`, `packages/db/src/migrations/`
**Issue**: On-disk and embedded migrations conflict at version 18
**Impact**: `subscription_only` column never created, latent runtime errors
**Approach**:
- Rename on-disk file to match embedded version
- Add migration to fix column if missing
- Update dual-loading logic to detect conflicts
**Testing**: Migration from both on-disk and embedded sources
**Effort**: 0.5 days

### 5. Unsalted SHA-256 API Key Hashing (HIGH)
**Files**: `packages/utils/src/crypto.ts`
**Issue**: `hashApiKey()` uses plain SHA-256 without salt
**Impact**: Rainbow table attacks if DB leaked
**Approach**:
- Add random salt to each key hash
- Store salt alongside hash in DB
- Migrate existing keys on next startup
**Testing**: Hash verification, migration correctness
**Effort**: 1 day

## P1 — Production Readiness (Near-term)

### 6. API Key Expiry & Scopes Enforcement (HIGH)
**Files**: `packages/db/src/migrations/`, `apps/gateway/src/middleware/auth.middleware.ts`
**Issue**: No key expiry, scopes/allowed_tools not enforced
**Impact**: SOC2 violations, overly permissive keys
**Approach**:
- Add `expires_at` column to `api_keys`
- Enforce scopes in auth middleware
- Add key rotation endpoint with persistence
**Testing**: Key expiry, scope enforcement
**Effort**: 1.5 days

### 7. Per-Tenant Rate Limits (HIGH)
**Files**: `apps/gateway/src/server.ts`, `services/quota/`
**Issue**: Gateway throttles per-IP only, not per-tenant
**Impact**: Noisy neighbor problem
**Approach**:
- Add tenant-level rate limiting middleware
- Use existing `quota_allocations` table
- Implement sliding window per tenant
**Testing**: Multi-tenant load testing
**Effort**: 1 day

### 8. Circuit Breaker State Machine (HIGH)
**Files**: `packages/utils/src/circuit-breaker.ts`
**Issue**: Half-open state allows unlimited requests
**Impact**: Cascading failures, retry storms
**Approach**:
- Fix half-open to allow single probe request
- Add proper state transitions (closed→open→half-open→closed)
- Persist circuit state for restart recovery
**Testing**: Failure injection, state machine verification
**Effort**: 1 day

### 9. Sticky Session TTL Eviction (HIGH)
**Files**: `services/router/src/sticky-session.ts`
**Issue**: No background cleanup, table grows unbounded
**Impact**: DB bloat, memory leaks
**Approach**:
- Add TTL to sticky session entries
- Implement background cleanup job
- Add index for efficient eviction queries
**Testing**: Long-running session cleanup
**Effort**: 0.5 days

### 10. Admin Audit Logging (HIGH)
**Files**: `apps/gateway/src/routes/admin.routes.ts`
**Issue**: No persistent log of admin actions
**Impact**: SOC2/ISO27001 compliance failure
**Approach**:
- Create `admin_audit_log` table
- Log all admin mutations (create/update/delete)
- Include timestamp, admin key hash, action, resource
**Testing**: Audit log completeness
**Effort**: 1 day

## P2 — UX & Performance (Future)

### 11. Real-time Dashboard Updates (MEDIUM)
**Files**: `apps/ui/`, `apps/gateway/src/`
**Issue**: Dashboard requires manual refresh
**Impact**: Stale data, delayed incident detection
**Approach**:
- Add WebSocket or SSE endpoint for live metrics
- Update dashboard components to subscribe
- Implement event-driven metric updates
**Testing**: Real-time update verification
**Effort**: 2 days

### 12. Mobile Responsive Design (MEDIUM)
**Files**: `apps/ui/src/`
**Issue**: No mobile breakpoints, sidebar layout
**Impact**: Can't manage on-call from mobile
**Approach**:
- Add responsive breakpoints for sidebar
- Implement hamburger menu for mobile
- Touch-friendly controls
**Testing**: Mobile device testing
**Effort**: 1.5 days

### 13. Request Caching (MEDIUM)
**Files**: `services/` (new cache service)
**Issue**: Zero caching for identical requests
**Impact**: Higher latency, wasted provider costs
**Approach**:
- Implement exact-match cache with TTL
- Add semantic cache using embeddings
- Per-tenant cache isolation
**Testing**: Cache hit rates, cost savings
**Effort**: 2 days

## Dependencies

- P0 fixes are independent, can be parallelized
- P1 items 6-7 depend on migration system (item 4)
- P2 items are independent of P0/P1

## Verification

After each fix:
1. Run `bun run test` (1250+ unit tests)
2. Run `bun run lint` and `bun run typecheck`
3. Manual testing of affected functionality
4. Security testing for P0 items

## Rollback Strategy

- All changes are additive (new columns, new tables)
- Database migrations are forward-only
- Feature flags for new functionality
- Graceful degradation if services unavailable
