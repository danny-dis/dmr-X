# Plan: Integrate Headroom Context Compression into DMR-X

## Executive Summary

Add Headroom as a configurable compression layer in DMR-X to reduce token costs and latency. Compression will be configurable at three levels: global, per-tenant, and per-API key, with UI switches for each.

## Integration Approach

### Option: Library Mode (Recommended)

Use Headroom's TypeScript library (`npm install headroom-ai`) directly in DMR-X's request pipeline. This gives:
- Full control over compression behavior
- No additional proxy process to manage
- Seamless integration with existing Fastify middleware

### Alternative Considered: Proxy Mode
- Requires running separate Headroom proxy process
- More operational complexity
- Better for external clients, not internal integration

### Phase 2: Create Compression Service

**New file: `packages/gateway/src/services/compression.ts`**

```typescript
import { compress, decompress, type CompressionOptions } from 'headroom-ai';

export interface CompressionConfig {
  enabled: boolean;
  algorithm: 'smartcrusher' | 'codecompressor' | 'kompress' | 'auto';
  reversible: boolean; // CCR enabled
  minTokensToCompress: number;
}

export class CompressionService {
  private defaultConfig: CompressionConfig = {
    enabled: false,
    algorithm: 'auto',
    reversible: true,
    minTokensToCompress: 100
  };

  async compressPrompt(
    messages: Message[],
    tenantConfig?: Partial<CompressionConfig>,
    apiKeyConfig?: Partial<CompressionConfig>
  ): Promise<{ compressed: Message[]; metadata: CompressionMetadata }> {
    const config = this.mergeConfig(tenantConfig, apiKeyConfig);
    if (!config.enabled) return { compressed: messages, metadata: { saved: 0 } };

    const result = await compress(messages, {
      algorithm: config.algorithm,
      reversible: config.reversible
    });

    return {
      compressed: result.messages,
      metadata: {
        originalTokens: result.originalTokens,
        compressedTokens: result.compressedTokens,
        saved: result.originalTokens - result.compressedTokens,
        algorithm: result.algorithmUsed
      }
    };
  }

  async retrieveOriginal(compressedId: string): Promise<Message[]> {
    return decompress(compressedId);
  }

  private mergeConfig(
    tenant?: Partial<CompressionConfig>,
    apiKey?: Partial<CompressionConfig>
  ): CompressionConfig {
    return { ...this.defaultConfig, ...tenant, ...apiKey };
  }
}
```

### Phase 4: Modify Gateway Request Pipeline

**File: `packages/gateway/src/index.ts`**

Add compression middleware before routing:

```typescript
import { CompressionService } from './services/compression';

const compressionService = new CompressionService();

// In request handler, before routing
app.addHook('preHandler', async (request, reply) => {
  const { tenantId, apiKeyId } = request.auth;
  
  // Get compression configs
  const tenantConfig = await getTenantCompressionConfig(tenantId);
  const apiKeyConfig = await getApiKeyCompressionConfig(apiKeyId);
  
  // Compress if enabled
  if (tenantConfig?.enabled || apiKeyConfig?.enabled) {
    const { compressed, metadata } = await compressionService.compressPrompt(
      request.body.messages,
      tenantConfig,
      apiKeyConfig
    );
    
    request.body.messages = compressed;
    request.compressionMetadata = metadata;
  }
});

// After response, decompress if needed
app.addHook('onSend', async (request, reply) => {
  if (request.compressionMetadata?.reversible) {
    // Store original in cache for retrieval
    await storeCompressionCache(request.compressionMetadata.id, request.originalBody);
  }
});
```

### Phase 5: Add Compression API Endpoints

**New file: `packages/gateway/src/routes/compression.ts`**

```typescript
import { FastifyInstance } from 'fastify';

export async function compressionRoutes(app: FastifyInstance) {
  // Get compression config for API key
  app.get('/api/v1/compression/config', async (request, reply) => {
    const { apiKeyId } = request.auth;
    return getApiKeyCompressionConfig(apiKeyId);
  });

  // Update compression config for API key
  app.put('/api/v1/compression/config', async (request, reply) => {
    const { apiKeyId } = request.auth;
    const config = request.body;
    return updateApiKeyCompressionConfig(apiKeyId, config);
  });

  // Retrieve original content (CCR)
  app.post('/api/v1/compression/retrieve', async (request, reply) => {
    const { compressedId } = request.body;
    return compressionService.retrieveOriginal(compressedId);
  });

  // Get compression stats
  app.get('/api/v1/compression/stats', async (request, reply) => {
    const { tenantId } = request.auth;
    return getCompressionStats(tenantId);
  });
}
```

export class OpenAIAdapter implements ProviderAdapter {
  async sendRequest(request: GatewayRequest): Promise<GatewayResponse> {
    const { messages, compressionMetadata } = request;
    
    // Messages are already compressed by middleware
    const response = await this.client.chat.completions.create({
      messages: messages.map(m => ({
        role: m.role,
        content: m.content
      })),
      // ... other params
    });

    return {
      response: response.choices[0].message,
      metadata: {
        ...response.usage,

  }

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Compression quality varies by content type | Use `auto` algorithm with ContentRouter |
| CCR cache storage grows | Implement TTL and cleanup job |
| Latency overhead from compression | Benchmark; cache hot paths |
| Breaking existing API contracts | Compression is opt-in, backwards compatible |
