# DMR-X Pre-Deployment UX/QA Audit Plan

## Project Summary

DMR-X is a universal AI routing and orchestration platform (v0.4.0) — a Fastify + React/Vite monorepo with 22 UI pages, 18 provider adapters, and SQLite backend. The admin dashboard manages providers, models, tenants, API keys, policies, memory, benchmarks, and settings.

---

## CRITICAL BUGS FOUND

### BUG-1 [SEVERITY: CRITICAL] — Settings form field name mismatches (data loss risk)

**File**: `apps/ui/src/props/Settings.tsx` lines 135, 145-146

The `fromServer()` function maps server fields to wrong property names that don't match the `SettingsForm` interface:

| `fromServer()` sets | `SettingsForm` expects | Impact |
|---|---|---|
| `autoFallback` (line 135) | `fallbackEnabled` | Fallback toggle reset on every load; unsaved changes detected falsely |
| `requireAuth` (line 145) | `requireApiKeyAuth` | Auth toggle never loads from server; always shows default |
| `corsOrigins` (line 146) | `allowedOrigins` | CORS config never loads; user edits are lost on save/load cycle |

**Fix**: Change `fromServer` lines 135, 145-146 to use the correct field names matching `SettingsForm`:
- `autoFallback` → `fallbackEnabled`
- `requireAuth` → `requireApiKeyAuth`
- `corsOrigins` → `allowedOrigins`

**Also**: The `dirty` check on line 307 (`JSON.stringify(form) !== JSON.stringify(fromServer(settings.data))`) will always detect "unsaved changes" for these fields, showing a persistent false-positive warning badge.

---

### BUG-2 [SEVERITY: MEDIUM] — Settings `toServer` field name drift

**File**: `apps/ui/src/pages/Settings.tsx` lines 172-212

The `toServer()` function sends `fallbackEnabled`, `requireApiKeyAuth`, and `allowedOrigins` to the server, but if the server expects `autoFallback`, `requireAuth`, or `corsOrigins`, the saved values won't persist. This needs verification against the backend admin routes — if the server also uses the `fallbackEnabled`/`requireApiKeyAuth`/`allowedOrigins` names, the bug is only in `fromServer`. If the server uses the old names, both `fromServer` AND `toServer` need fixing.

---

### BUG-3 [SEVERITY: LOW] — Duplicate commented code in admin.ts

**File**: `apps/ui/src/lib/admin.ts` lines 117-131, 254-261, 273-279

Multiple TODO comments with duplicate `getProvider`, `getModel`, `getTenant` methods. The first instance is commented out, then the second is active. This is messy but not a runtime issue.
