# Free Tier Dashboard Design Plan

## Overview

Design a dedicated "Free Tier" dashboard section that provides users with a streamlined interface to manage and monitor free-tier AI providers, with integrated credential management, usage tracking, and direct access to provider signup pages.

---

## User Journey

### Entry Point
1. User accesses `/free-tier` route via sidebar navigation
2. Prominent "Add Free Provider" button on page header
3. Quick stats overview (available providers, active connections, budget remaining)

### Workflow
```
Entry → Overview → Add Provider → Configure/API Key → Monitor Usage → Manage/Remove
```

## Functional Requirements

### 1. Provider Management

**Components:**
- `FreeTierPage.tsx` - Main dashboard page
- `FreeProviderCard.tsx` - Enhanced provider card for free providers
- `AddFreeProviderDialog.tsx` - Modal for adding free providers
- `FreeProviderDrawer.tsx` - Slide-out panel for provider details

**API Integration:**
```typescript
// Extend existing admin.ts
Admin.listFreeProviders()
Admin.activateFreeProvider(templateId, apiKey)
Admin.updateFreeProviderApiKey(id, apiKey)
Admin.testFreeProvider(id)
```

**Features:**
- One-click activation from catalog (template_id)
- Bulk enable/disable free models
- Provider categorization (LLM, Diffusion, Embedding, Audio)
- Health status badge with real-time updates

### 2. Credential Storage

**UI Components:**
- Secure input field (masked by default, show on hover/focus)
- "Save" and "Test" buttons inline
- Key rotation reminder (optional)
- OAuth flow support for providers (GitHub, Google, HuggingFace)

**Backend Integration:**
- Uses existing `/v1/admin/providers/activate` endpoint
- API keys encrypted via AES-256-GCM (existing `encrypt()` utility)
- OAuth token storage (existing implementation in admin.routes.ts)

**Visual Indicators:**
```
[KeyRound icon] API Key configured
[ OAuth badge] Connected via OAuth (expires in 4 days)
[No key icon] No key required (local/ollama)
```

### 3. Direct Access to Provider Sign-in

**Link Resolution:**
Each catalog entry includes `signupUrl`:
```typescript
// provider-catalog.ts already has signupUrl field
{
  id: 'openrouter-free',
  name: 'OpenRouter (Free)',
  signupUrl: 'https://openrouter.ai/signup',
  ...
}
```

**UI Implementation:**
- "Get API Key" button opens `signupUrl` in new tab
- Tooltip shows URL before clicking
- Disabled state if no signup URL available (e.g., Ollama)

### 4. Tracking & Visibility

**Metrics Display:**
- Monthly token budget progress bar
- Request count (24h, 7d, 30d)
- Success rate percentage
- Average latency
- Health status with last check time

**API Endpoints Needed:**
- Extend `ApiProvider` with free-tier specific fields:
```typescript
interface ApiFreeTierProvider extends ApiProvider {
  freeTierMetadata?: {
    monthlyTokenBudget: number;
    monthlyTokenUsed: number;
    rateLimits: { rpm: number; rpd: number; tpm: number; tpd: number };
    intelligenceRank: number;
    speedRank: number;
  };
  usage24h?: number;
  successRate?: number;
}
```

## Security Considerations

1. **API Key Display:**
   - Never show full key in UI (mask all but last 4 chars)
   - Use existing `maskKey` formatter
   - No key retrieval from backend (write-only)

2. **OAuth Flow:**
   - Reuse existing OAuth implementation
   - State parameter validation
   - Token refresh handled automatically

3. **Rate Limit Visibility:**
   - Show user's consumption relative to provider limits
   - Warn when approaching limits
