# Fix for Tenant/Policy Creation Failures in DMR-X

## Problem
Users were experiencing 401/403 Unauthorized/Forbidden errors when trying to create tenants or policies via the admin API endpoints (`/v1/admin/tenants`, `/v1/admin/policies`, etc.) even when running in local mode.

## Root Cause
The issue was with environment variable loading:
1. The `.env` file containing `DMRX_LOCAL_MODE=true` is located in the project root directory
2. The `dev:gateway` script was using `bun run --cwd apps/gateway dev`, which changes the working directory to `apps/gateway` before starting the server
3. Bun's automatic `.env` loading only looks for `.env` files in the current working directory
4. As a result, the `.env` file was not being loaded, making `process.env.DMRX_LOCAL_MODE` undefined
5. This caused the authentication middleware to evaluate `LOCAL_MODE` as `false`
6. When `LOCAL_MODE` is `false`, admin routes require authentication, leading to 401/403 errors

## Solution
Modified the `dev:gateway` script in the root `package.json` to run the gateway server from the project root directory:

**Changed from:**
```json
"dev:gateway": "bun run --cwd apps/gateway dev"
```

**Changed to:**
```json
"dev:gateway": "bun --watch apps/gateway/src/main.ts"
```

This ensures:
- Working directory remains the project root (where `.env` file is located)
- Bun's automatic `.env` loading can find and load environment variables
- `process.env.DMRX_LOCAL_MODE` correctly evaluates to `"true"`
- Authentication middleware properly sets `LOCAL_MODE = true`
- Admin routes skip authentication in local mode

## Verification
After the fix, startup logs confirm correct environment variable loading:
```
{"level":30,"time":1780521310659,"pid":9604,"hostname":"DESKTOP-CCL5G81","name":"dmr-x","localMode":true,"adminKeySet":true,"envValue":"true","msg":"Auth middleware status"}
```

## To Start the Server
Run the following command from the project root directory:
```
bun run dev:gateway
```

The server will now correctly recognize local mode and allow admin API calls (tenant/policy creation, etc.) without requiring authentication headers.
