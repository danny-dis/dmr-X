# DMR-X MCP — 2026 Integration Specification

**Updated:** 2026-09-06  
**Target:** MCP 2026-07-28 and compatible clients

## Role

DMR-X uses MCP as an interoperability/interface layer. MCP exposes DMR-X capabilities to compatible agents and can optionally aggregate external MCP servers.

MCP is **not** the DMR-X orchestration brain.

The official 2026-07-28 MCP release introduced a stateless protocol core, Multi Round-Trip Requests, header-based routing, cacheable list results, authorization hardening, Tasks and a formal extensions framework. DMR-X documentation and conformance tests should track that generation rather than assuming the older session-oriented model is canonical.

## DMR-X MCP surfaces

### DMR-X capabilities

Expose capabilities such as:

- routed inference
- model discovery
- route preview
- routing decision inspection
- multimodal inference
- agent/runtime management where authorized
- skill discovery
- job/task inspection
- administrative operations according to tenant permissions

### External MCP aggregation

DMR-X may act as an MCP gateway to external servers.

Every upstream server must have:

- stable server identity
- namespace
- connection policy
- tool allowlist
- credentials isolated from unrelated servers
- health state
- timeout/concurrency limits
- provenance metadata

## Tool discovery

Do not send the complete external tool universe to every model.

Use capability-aware discovery:

`task requirements -> candidate tools -> policy filter -> trust/health filter -> rank -> expose minimal tool set`

Ranking signals should include:

- semantic relevance
- capability fit
- historical success
- latency
- cost
- reliability
- trust
- tenant policy

## Tool metadata

Each tool should eventually expose normalized metadata for:

- read-only vs side-effecting
- destructive vs non-destructive
- idempotent vs non-idempotent
- network/open-world behavior
- required permissions
- expected latency
- timeout
- retry safety
- version
- provenance

## Security

- authenticate remote MCP clients;
- authorize per tenant/client/tool;
- validate JSON Schema inputs;
- validate outputs where feasible;
- isolate secrets;
- restrict network egress;
- prevent SSRF through remote-server configuration;
- detect prompt injection in untrusted tool results;
- apply output DLP/PII policy;
- maintain auditable tool-call records;
- support cancellation and bounded execution.

## Reliability

For upstream MCP servers implement:

- connection health
- circuit breakers
- bounded reconnects
- concurrency limits
- timeouts
- per-server rate limits
- graceful degradation
- error normalization
- per-tool latency/error metrics

## Current-spec compatibility plan

Build a compatibility matrix covering:

- stdio
- Streamable HTTP
- stateless remote requests
- discovery
- tool list caching
- header-based method/name routing
- authorization
- Tasks where implemented
- extensions
- cancellation
- malformed requests
- oversized requests
- upstream failures

Legacy SSE support may remain for compatibility, but new remote deployments should prefer the current transport defined by the supported MCP specification.

## DMR-X-specific rule

MCP can expose DMR-X's runtime and routing capabilities, but every operation still enters DMR-X's normal authentication, authorization, policy and execution boundaries.

An MCP client cannot use MCP as a privilege-escalation path.
